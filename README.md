# VlessSharingPanel

Закрытая панель на Rust для выдачи отдельных VLESS/REALITY-профилей. Владелец загружает **уже выпущенный** клиентский `vless://` URI, создаёт ссылку и случайный пароль для получателя. Получатель видит URI и QR только после ввода пароля. Панель не читает серверные ключи и не изменяет Xray или WireGuard.

## Что работает

- Вход владельца по паролю и TOTP, короткая сессия, защита форм от CSRF.
- Создание записи для человека и устройства, срок и лимит открытий, продление и отзыв ссылки.
- Секретный токен ссылки хранится только в виде SHA-256; пароль — Argon2id; URI — XChaCha20-Poly1305. Ключ шифрования хранится отдельно от SQLite.
- Мобильная страница получателя с QR и кнопкой копирования. CSS и JavaScript локальные, без CDN.
- Запасная CLI для создания/отзыва/продления ссылок и просмотра списка без секретов.

**Граница функций:** отзыв ссылки немедленно закрывает страницу, но уже импортированный профиль продолжит работать, пока UUID не удалён из Xray. Создание UUID и изменение Xray пока выполняются существующими скриптами на VPS РФ. Не выдавайте один UUID нескольким людям. [Контекст сети](docs/CONTEXT.md).

## Быстрый запуск для разработки

Нужен Rust stable. В отдельном терминале:

```sh
mkdir -p /tmp/vless-panel-demo
printf '%s\n' 'очень-длинный-тестовый-пароль' | cargo run -- --data-dir /tmp/vless-panel-demo init
PANEL_PUBLIC_URL=http://127.0.0.1:3000 cargo run -- --data-dir /tmp/vless-panel-demo serve
```

При `init` сохраните показанный TOTP-секрет в приложении-аутентификаторе. Откройте `http://127.0.0.1:3000/`. HTTP разрешён только для локальной разработки; для получателей нужен доверенный HTTPS.

CLI создаёт ссылку, читая URI из stdin (без аргумента командной строки):

```sh
PANEL_PUBLIC_URL=https://your-host.example \
  cargo run -- --data-dir /path/outside/repository issue --person Ivan --device iPhone < client-profile.txt
cargo run -- --data-dir /path/outside/repository list
cargo run -- --data-dir /path/outside/repository revoke 1
```

`client-profile.txt` должен быть файлом с правами `0600`, содержащим URI клиента, который **уже добавлен в Xray**. URI, ссылка и пароль не должны попадать в Git, shell history или логи. Пароль и полная ссылка показываются один раз; при утрате создайте новую запись и отзовите старую.

## Размещение на VPS РФ

Сборка и обновление по тегу через GitHub Actions описаны в [инструкции деплоя](deploy/README.md). Workflow проверяет код, собирает статический бинарник и откатывает неудачное обновление.

Сервис принимает соединения только на `127.0.0.1` или `::1`. Публичный HTTPS reverse proxy должен передавать запросы на локальный порт панели. `PANEL_PUBLIC_URL` задаётся как внешний HTTPS origin без пути. Cookie входа помечена `Secure`, `HttpOnly`, `SameSite=Strict`; обратный прокси обязан передавать `Origin` без изменения и не писать путь `/s/…`, тела запросов и ответов в журналы.

Не занимайте действующий `443` Xray VLESS/REALITY. Владелец выбрал VPS РФ и пока не имеет домена, поэтому внешний HTTPS-адрес и порт нужно определить после проверки доступных портов и возможности получить доверенный сертификат для IP. До этого панель может использоваться владельцем по SSH-туннелю для выдачи URI вручную, но ссылка получателя не должна публиковаться по HTTP.

Запускайте процесс отдельным непривилегированным пользователем с каталогом данных `0700` вне репозитория. Не выдавайте ему root, Docker socket и доступ к `/root/vless-ru-meta.json`. Сделайте отдельные защищённые копии SQLite и файла `key`; без ключа профили из базы не восстановить. Каталог данных нельзя помещать в публичный Git-репозиторий.
