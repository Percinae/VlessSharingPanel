# Какие приложения используют VLESS

Начальный список владельца: **WhatsApp, Telegram, Google Chrome**. Позже его можно расширить. Это настройка устройства, а не сервера: `vless://` URI содержит параметры подключения, но не список процессов или Android-приложений. Серверная маршрутизация РФ/NL применяется только к трафику, который мобильный клиент направил в VLESS.

## Android: v2rayNG

1. Импортируйте профиль и включите VPN-режим v2rayNG.
2. Откройте **Settings → Per-app proxy** (название в переводе может быть «Прокси для приложений»). Включите **Enable per-app**.
3. **Bypass Mode выключен**: в обычном режиме отмеченные приложения используют прокси, остальные подключаются напрямую. В режиме Bypass логика обратная.
4. Отметьте WhatsApp, Telegram и Chrome в списке приложений. Если установлены разные версии Telegram или несколько профилей Android, выберите нужные экземпляры. Добавляйте другие приложения в тот же список.
5. Перезапустите VPN. Проверьте выбранные приложения и одно невыбранное. Не выбранное должно работать без VLESS; выбранное при активном VPN идёт через VPS РФ, где уже применяется разделение РФ/NL.

Эта настройка хранится в v2rayNG на конкретном Android-устройстве. Повторный импорт одной VLESS-ссылки на другом устройстве не перенесёт выбор приложений. В исходном коде v2rayNG режим с выключенным Bypass вызывает Android `addAllowedApplication()` только для выбранных пакетов: [CoreVpnService.kt](https://github.com/2dust/v2rayNG/blob/ef06bac9942a8550217ebe057daefd28964d436d/V2rayNG/app/src/main/java/com/v2ray/ang/service/CoreVpnService.kt#L257-L295). Смысл переключателя описан в [строках интерфейса](https://github.com/2dust/v2rayNG/blob/ef06bac9942a8550217ebe057daefd28964d436d/V2rayNG/app/src/main/res/values/strings.xml#L174-L189).

## Windows: v2rayN

Для отбора по программам нужен режим, который видит процессы, например **sing-box с TUN** и правила маршрутизации по именам или путям процессов. В модели правил v2rayN есть поле `Process`; при генерации конфигурации sing-box оно превращается в `process_name` или `process_path`: [RulesItem.cs](https://github.com/2dust/v2rayN/blob/f57b1bf47961f0d39c690887cf9a2e6941fb1276/v2rayN/ServiceLib/Models/Entities/RulesItem.cs), [SingboxRoutingService.cs](https://github.com/2dust/v2rayN/blob/f57b1bf47961f0d39c690887cf9a2e6941fb1276/v2rayN/ServiceLib/Services/CoreConfig/Singbox/SingboxRoutingService.cs#L462-L503).

В v2rayN создайте правила для фактических исполняемых файлов WhatsApp, Telegram и Chrome с выходом **proxy**; для остальных процессов задайте **direct**. Имена процессов проверьте в Диспетчере задач Windows: у WhatsApp и версий из Microsoft Store они могут отличаться. Перед постоянным использованием проверьте, что невыбранный браузер выходит напрямую, а выбранный Chrome — через VLESS. Простой системный прокси Windows не гарантирует такой отбор: программы могут по-разному использовать системные настройки.

## iPhone/iPad: Shadowrocket пока под вопросом

Для обычного iPhone/iPad с Shadowrocket мы не обещаем строгий список WhatsApp/Telegram/Chrome. Правила Shadowrocket по доменам и IP выбирают **назначение соединения**, а не приложение. Они не дают гарантии «Chrome целиком через VLESS, остальные программы напрямую», потому что Chrome может открывать любой сайт, а приложения могут разделять адреса.

Apple поддерживает настоящий per-app VPN для **управляемых приложений** через службу управления устройствами (MDM); для обычного установленного пользователем приложения это не равнозначно настройке списка в VLESS-профиле. Apple рекомендует уточнять поддержку у поставщика конкретного VPN-решения: [VPN overview for Apple device deployment](https://support.apple.com/guide/deployment/vpn-overview-depae3d361d0/web). Пока клиент для iPhone не выбран окончательно, безопасный вариант — не выдавать настройку по доменам за строгое правило по приложениям.
