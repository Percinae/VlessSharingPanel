# Контекст из чата «Настроить маршрутизацию WireGuard»

Источник: [чат Codex](codex://threads/01a1b074-e180-7690-98b5-64473f80e52b), состояние на 15 ноября 2026 года. Здесь оставлены только детали, нужные проекту. В публичный репозиторий не внесены реальные UUID, VLESS URI, ключи, пароли и домен маскировки REALITY.

- На VPS РФ уже работает Xray VLESS/REALITY на `443`. Любой добавленный VLESS-клиент попадает под серверные правила маршрутизации.
- Адреса РФ (IPv4 и IPv6) выходят с VPS РФ. Зарубежный IPv4 идёт через основной VPS NL с резервом; зарубежный IPv6 — через резервный VPS NL. Панель не должна менять эти правила.
- Каждый друг и устройство должны иметь отдельный UUID. Действующий реестр клиентов на VPS РФ: `/root/vless-ru-meta.json`; он содержит в том числе серверный приватный ключ, поэтому веб-процессу к нему доступ запрещён.
- Существующие скрипты на VPS РФ: `/root/ru-rebuild/setup-vless-ru.py` для применения конфигурации и `/root/ru-rebuild/export-vless-clients.py` для экспорта URI. Готовые URI находятся в `/root/ru-rebuild/client-profiles/`. Эти пути нужно перепроверить на VPS перед интеграцией.
- Для клиента VLESS режим VPN/TUN и DNS через туннель нужны, если требуется направить через VPS всё устройство. «РФ в РФ» означает выход из VPS РФ, а не прямой выход через домашнего провайдера клиента.
- Веб-портал размещается на VPS РФ. Домена у владельца пока нет; VLESS занимает `443`. Для публичной страницы требуется отдельный проверенный HTTPS-адрес, не меняющий рабочий Xray.

Следующий этап интеграции: отдельный локальный помощник с узкими правами на VPS РФ должен создавать и удалять UUID, проверять конфигурацию Xray и неизменность маршрутов, применять её с откатом и передавать панели только URI одного созданного клиента. Такой помощник нельзя безопасно подключить без чтения реальных скриптов и структуры конфигурации VPS.
